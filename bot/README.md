# @gramhistorybot

Inline-бот на **puregram 3.10.0**, Node.js 24 и Luxon 3.7.2. Запускается на сервере отдельным сервисом Docker Compose. Читает существующий API по внутреннему адресу `http://api:8087`; прямого доступа к базе и запросов в Calcmula у бота нет.

## Использование

В любом чате Telegram:

```text
@gramhistorybot 24.04.22
@gramhistorybot 24.04.2022 15:30
@gramhistorybot 24.04.22 15:30 UTC+5
@gramhistorybot 24.04.22 15:30 Europe/Berlin
@gramhistorybot 2022-04-24T15:30:00+03:00
@gramhistorybot сегодня
@gramhistorybot yesterday at 15:30
@gramhistorybot месяц назад
@gramhistorybot 3 days ago
@gramhistorybot две недели назад в 12:00 UTC+5
@gramhistorybot now
```

- Дата без времени → первая, последняя, минимальная и максимальная цены за календарный день.
- Дата со временем → последняя запись не позже указанного момента, не старше 15 минут. Фактическое время записи видно в ответе.
- `22` означает 2022; двузначные годы всегда относятся к 2000–2099.
- Telegram **не передаёт часовой пояс** в inline query или объекте User. По умолчанию используется **Europe/Moscow (МСК)**. Язык профиля и место размещения сервера не используются для определения пояса.
- Явное смещение поддерживается для точного времени, включая `UTC+05:30`. Для дневной сводки доступны IANA-пояса и смещения в целых часах; для дробного смещения укажите, например, `Asia/Kolkata`.
- Неоднозначное время при осеннем переводе часов требует явного UTC-смещения; несуществующее время отклоняется.
- Будущая дата, пропуск, пустая история и недоступность API дают понятную карточку вместо выдуманной цены.

### Даты словами

| Русский | English | Что возвращается |
| --- | --- | --- |
| сегодня, сег | today | Сводка за текущий день |
| вчера, вч | yesterday, yday, yest | Сводка за вчера |
| позавчера | day before yesterday | Сводка за два дня назад |
| неделю назад, прошлая неделя | a week ago, last week, previous week | Та же дата семь дней назад |
| месяц назад, прошлый месяц | a month ago, last month, previous month | Та же дата месяц назад |
| год назад, прошлый год | a year ago, last year, previous year | Та же дата год назад |
| полгода назад | half a year ago | Та же дата шесть месяцев назад |
| 3 дня назад, три дня назад | 3 days ago, three days ago | Сводка за указанную дату |
| две недели назад, пару недель назад | 2 weeks ago, two weeks ago | Сводка за указанную дату |
| сейчас, теперь, текущий курс, актуальный курс | now, right now, latest, current, current price | Цена на момент запроса |
| час назад, 2 часа назад | an hour ago, 2 hours ago | Цена на момент в прошлом |
| полчаса назад, 30 минут назад | half an hour ago, 30 minutes ago | Цена на момент в прошлом |

Поддерживаются секунды, минуты, часы, дни, недели, месяцы и годы; числа можно писать цифрами либо словами от одного до десяти. Есть сокращения вроде `3d ago`, `2h ago`, `5 мин назад`, `2 нед. назад`. Регистр и лишние пробелы не важны. Допустимы вводные `на сегодня`, `за вчера`, `as of yesterday`.

К календарной дате можно дописать время: `вчера 15:30`, `вчера в 15:30`, `yesterday at 15:30`, а затем часовой пояс: `UTC+5`, `МСК`, `Europe/Berlin`. Дни считаются в этом поясе; без него — в МСК. `last week/month/year` означает конкретный день в прошлом, а не сводку за весь период. Месяцы и годы календарные: 31 марта минус месяц — 28 или 29 февраля. «Сегодня» показывает неполную сводку, пока день продолжается. Для `now` и отступов в часах/минутах/секундах применяется обычный предел свежести записи 15 минут.

Относительная дата фиксируется при получении inline-запроса. Момент отсчёта помещается в ID результата, поэтому выбор после полуночи или перезапуска бота не меняет дату, показанную в выдаче. Парсер работает локально в процессе бота, без внешних сервисов и запросов к нейросетям.

Результат отправляется как настоящий **InputRichMessageContent** (`rich_message.html`) — заголовки, таблицы, форматирование, раскрываемая информация об источнике и кнопки. В дневной сводке цены, время первой/последней записи и число наблюдений находятся в одной таблице с границами и чередованием строк. Примечания о пропусках и min/max объединены в один короткий footer без принудительных переносов. Это не обычный `sendMessage` с `parse_mode`. Для Rich Messages нужен Telegram-клиент с поддержкой этой функции. `/start` и `/help` показывают примеры; в личном чате бот также принимает даты.

При inline-запросе даты выдача содержит готовые заголовок и описание, но в чат сначала отправляется `Loading...` с временной inline-клавиатурой. После `chosen_inline_result` бот получает данные API и заменяет сообщение через `editMessageText.rich_message`. Клавиатура нужна Telegram для выдачи `inline_message_id`; при редактировании она удаляется, а две итоговые кнопки находятся внутри Rich Message. Текст запроса берётся из события выбора, поэтому механизм не зависит от сохранённого в памяти списка результатов и работает после перезапуска. Перед заменой выбранного результата выдерживается минимум 400 мс от получения feedback, даже при попадании цены в кэш, чтобы разделить Loading и Rich Message. Справка и ошибки ввода показываются сразу. При временных ошибках редактирования есть до двух повторных попыток; если Telegram отклонит Rich Message, вместо загрузки появляется сообщение с предложением повторить запрос.

Карточка бота показывает одну таблицу в USD за весь день: первая и последняя цены выбираются по времени, минимум и максимум — по всем сегментам, наблюдения суммируются. Старый участок USDT отображается как приблизительный USD по условному соотношению 1:1 с пометкой «USDT ≈ USD (1:1)» в footer; это относится и к точечным запросам. API и база сохраняют исходные валюты и отдельные сегменты. Десятичные строки сравниваются без JavaScript Number и округления. Незавершённый день и большие промежутки, включая разрыв между источниками, помечаются.

Над таблицей нет отдельного заголовка источника: валюта указана возле каждой цены. В раскрываемом блоке «Об источнике» находится описание архива @tonprices и дальнейшего обновления через calcmula.app каждые 5 минут. Заголовок GRAM, строка «Сводка за день» и показатели таблицы используют заданные ID в явных объектах `RichTextCustomEmoji` (`type: custom_emoji`). Карточки цен передаются через `rich_message.blocks`, без HTML-разбора эмодзи. Первая цена и первая запись имеют одну иконку; последняя цена и последняя запись — другую. Максимум расположен перед минимумом. Кнопки «Другая дата» и «Об API» находятся в блоке `buttons` перед footer, их текст содержит явные custom emoji. Обычная inline-клавиатура к карточке не добавляется. Идентификаторы хранятся строками в `src/render.js`; обычные emoji служат `alternative_text`, а не заменяют custom emoji в отправляемых данных.

## Запуск на сервере

Токен хранится **только на сервере** в `secrets/telegram_bot_token` и монтируется как Docker secret. Он отсутствует в исходниках, образе, архиве и логах. Файл должен быть доступен на чтение UID 1000 контейнера (например, владелец `1000:1000`, режим `0400`, родительский каталог `0700` владельца root).

При переносе проекта создайте этот файл на новом сервере и выполните из корня проекта:

```sh
docker compose build bot
docker compose run --rm --no-deps bot npm test
docker compose up -d --no-deps bot
docker compose logs --tail=20 bot
```

Если нужен только API, можно по-прежнему запускать `docker compose up -d api collector exporter` без бота. Для другого способа развёртывания поддерживаются `TELEGRAM_BOT_TOKEN_FILE` или `TELEGRAM_BOT_TOKEN` и `PRICES_API_URL`; фактический токен не добавляйте в исходники.

В BotFather требуется `/setinline`, выбрать `@gramhistorybot`, задать подсказку `Дата: 24.04.22 или 24.04.22 15:30`. Затем обязательно `/setinlinefeedback` → `@gramhistorybot` → **100%**: иначе часть или все сообщения останутся `Loading...`, потому что бот не получит событие выбора. Проверка inline-режима — `getMe.supports_inline_queries=true`; доставку feedback проверяют по событию `inline_edited` в логах после выбора результата. Через Bot API эти настройки не включаются. Существующий webhook автоматически не удаляется.

Бот использует long polling, обрабатывает до 16 запросов одновременно, не открывает внешний порт, автоматически перезапускается Docker. Проверка здоровья контролирует последние успешные ответы getUpdates. При зависании polling процесс завершится и будет перезапущен. Обновления сообщений из групп игнорируются.

Ответы Telegram не кэшируются (`cache_time=0`, `is_personal=true`). При наборе inline-запроса цены не запрашиваются — запрос выполняется только после выбора. Одинаковые запросы к API объединяются; локальный кэш ограничен 512 элементами: 5 секунд для текущего дня и 60 секунд для исторических запросов. Таймаут API — 3 секунды. Логи содержат тип ответа и длительность, без ID пользователей и текста запросов. Метрики включают `inline_edited`, `inline_edit_failed` и `inline_chosen_no_id`.

## Проверки

```sh
cd bot
npm ci --ignore-scripts
npm test
npm run check
```

Тесты выполняются без токена, сервиса и сетевых запросов: календарь, часовые пояса/DST, точность строк, USD/USDT, Rich Message payload, inline-обработчик, пустые ответы, ошибки, дедупликация и обновление кэша.

Официальные источники: [puregram](https://github.com/puregram/puregram), [InlineQuery](https://core.telegram.org/bots/api#inlinequery), [InputRichMessageContent](https://core.telegram.org/bots/api#inputrichmessagecontent).
