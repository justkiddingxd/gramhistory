# Скорость TON Prices API

Замер 27 сентября 2026 года на сервере проекта, HTTP к `127.0.0.1:8087`, постоянное соединение. До изменения — 20 измерений после пяти прогревочных запросов; после — 100 измерений после пяти прогревочных. Это полное время HTTP-ответа внутри сервера, без внешней сети и Cloudflare. Цифры не являются гарантией задержки под любой нагрузкой.

Первый запрос покрытия после создания или сброса кэша потребовал 136,447 мс. Остальные методы не используют кэш цен. Первый исторический запрос в серии после развёртывания потребовал 5,312 мс; далее — значения из таблицы.

Дополнительная проверка с восемью одновременными клиентами: 160 смешанных запросов цены, сводки, текущей цены и покрытия; ошибок нет, медиана 13,174 мс, p95 147,145 мс. Это отдельный результат под нагрузкой, а не обещание той же задержки, что у последовательных прогретых запросов. Журнал — `.deploy/benchmark-concurrent.json`.

## Что изменено

- Точечный поиск обращается к составному индексу с одной верхней границей. Предыдущая лишняя граница перехода на Calcmula заставляла SQLite просматривать поздние записи перед попаданием в нужный момент.
- Дневные и исторические диапазоны заранее разделяются по источникам; каждая таблица получает одну точную пару границ. Нет чтения всего архива ради одной даты.
- Итоги покрытия кэшируются в памяти для четырёх разрешённых серий. SQLite `data_version` сбрасывает кэш после зафиксированных изменений, без временной задержки TTL. Последнее состояние сборщика читается в том же снимке базы. Новая цена и запросы по датам не ждут обновления кэша.
- API отвечает из своей базы и не делает запросов к Calcmula во время пользовательского запроса.

43 автоматические проверки прошли, включая точность десятичных строк, даты/временные зоны, неполный день, пустой день, смешанные валюты, пагинацию через переход источников, инвалидирование кэша после записи и ограничение количества операций индексного поиска. Сборщик продолжает работать отдельным контейнером.
