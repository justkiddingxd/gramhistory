# Gram Prices API

Базовый адрес: `https://gram.rin.ms`. Все методы ниже используют `GET`, API-ключ не нужен. Актив API — TON (`asset_id: toncoin`); название сервиса Gram Prices не обозначает другой актив.

Эта инструкция: [skill.md](https://gram.rin.ms/skill.md). Полные модели и ограничения: [OpenAPI](https://gram.rin.ms/openapi.json). Человеческая документация: [docs](https://gram.rin.ms/docs).

## Подключение

Для JSON-запросов передавай заголовки:

```http
Accept: application/json
User-Agent: GramPricesClient/1.0
```

Cloudflare может отклонить стандартную подпись Python `urllib` кодом `403 / 1010` до обращения к API. Явный User-Agent выше проверен. Такой ответ может быть текстом, поэтому сначала проверь HTTP-статус и Content-Type, затем разбирай JSON.

## Выбор запроса

| Потребность | Метод и параметры |
|---|---|
| Текущая цена | `/v1/ton/price/latest` |
| Сводка за календарный день | `/v1/ton/price?at=2024-02-05&timezone=Europe/Moscow` |
| Одна цена на точный момент | `/v1/ton/price?at=2024-02-05T09:00:00Z` |
| Наблюдения за период | `/v1/ton/history?from=2024-02-05T00:00:00Z&to=2024-02-06T00:00:00Z` |
| Отдельный маршрут дневной сводки | `/v1/ton/daily?date=2024-02-05&timezone=Europe/Moscow` |
| Покрытие данных и состояние сбора | `/v1/ton/coverage` |

Не загружай историю целиком ради одной цены или сводки: для них есть отдельные запросы.

### Простая дата — сводка, а не одна цена

`at=YYYY-MM-DD` возвращает `data.kind: "daily_summary"`. В каждом элементе `data.segments` находятся:

- `first`, `last`, `min`, `max` — первая, последняя, минимальная и максимальная сохранённые цены;
- `first_at`, `last_at` — время первой и последней записей;
- `quote_currency`, `series`, `providers`, `points_count` — валюта, серия, источник и число наблюдений.

Используй указанный пользователем часовой пояс. Параметр `timezone` принимает название IANA, например `Europe/Moscow`; по умолчанию используется UTC. Если пояс не указан, можно использовать UTC, явно обозначив это в ответе. Уточни его, если выбор существенно меняет ответ на запрос пользователя.

Границы дня — `[data.from, data.to)`. Сегодняшний день возвращается с `is_day_complete: false`. Будущая дата не поддерживается. День без данных возвращает HTTP 200, `segments: []` и предупреждение `NO_DATA`; это не нулевая цена.

Не подменяй дневную сводку её последней ценой. Если пользователь просит одну цену в определённое время, передай полный момент времени.

### Точное время — одна цена

Передавай RFC 3339 с секундами и часовым поясом: `2024-02-05T09:00:00Z` или `2024-02-05T12:00:00+03:00`. Используй параметры HTTP-клиента для кодирования URL: знак `+` должен стать `%2B`.

API выбирает последнюю запись **не позднее** запрошенного момента. Между наблюдениями нет интерполяции. Ответ содержит `data.price`, `quote_currency`, `requested_at`, фактическое `observed_at`, `age_seconds` и `source.provider`.

`max_age_seconds` ограничивает возраст записи: по умолчанию 900, допустимо 0–86400. Ограничение относится к точному времени и `/price/latest`, но не к дневной сводке. Не увеличивай его незаметно, чтобы скрыть пропуск или устаревание. Параметр `timezone` применяется только к простой дате; полный момент использует своё смещение.

## Полная база

`GET https://gram.rin.ms/v1/ton/export` скачивает все таблицы SQLite в gzip, включая исходные сообщения публичного канала. Это бинарный `application/gzip`, не JSON. Передавай `Accept: application/gzip` и сохраняй ответ потоком в файл `.sqlite3.gz`, затем распакуй gzip. Не читай весь файл в память и не пытайся разобрать его как JSON.

Снимок готовится отдельно каждые 5 минут. `HEAD` возвращает размер, `X-Snapshot-Created-At`, возраст и `X-Checksum-SHA256` сжатого файла. `ETag` / `If-None-Match` поддерживают 304. 503 `EXPORT_UNAVAILABLE` означает, что снимок ещё не готов; `EXPORT_STALE` — старше 15 минут. Учитывай `Retry-After`. Частичная загрузка Range не поддерживается. Для аналитики в SQLite используй представление `price_observations`; точные строки цен и разные валюты сохраняются.

## Источники и точность

Методы котировок принимают `series`; полная выгрузка `/export` не фильтруется:

- `reference` — по умолчанию: архив Telegram до перехода на Calcmula, затем Calcmula. В `/coverage` поле `data.cutover_at` обозначает начало Calcmula, а `data.usd_cutover_at` — переход с прежних USDT на USD. После второго перехода текущая цена — USD.
- `telegram-usd` — архив @tonprices с 15 декабря 2021 года. USD означает знак `$` в исходном канале; первоначальный источник котировки неизвестен. Экспорт отражает сохранённый текст сообщений, включая редакции.
- `calcmula-usd` — текущие наблюдения TON/USD: запрос к Calcmula `1 ton in usd`, сбор каждые пять минут.
- `calcmula-usdt` — прежние наблюдения TON/USDT до переключения на USD. Сбор этой серии прекращён; исторические значения сохранены без пересчёта.
- `market-usdt` — зарезервировано; данных пока нет.

USD и USDT не пересчитываются друг в друга. Проверяй валюту каждой записи; дневные сводки разделяют источники и валюты на сегменты. Не объединяй их в одну среднюю, минимум или максимум без явно заданного правила пересчёта.

Цены передаются строками. Для вычислений используй `Decimal` или другую точную десятичную арифметику. Не меняй точность значения без необходимости и не извлекай цену из текста примеров документации.

Для Calcmula `observed_at` — время получения ответа, `timestamp_basis: "retrieval_time"`, `provider_updated_at: null`. Время обновления самого рыночного курса неизвестно. Пять минут — период сбора, а не гарантия отсутствия пропусков. Дневная сводка — статистика сохранённых наблюдений, не биржевая OHLC-свеча.

## История и пагинация

`from` и `to` требуют полных RFC 3339 timestamps. Диапазон `[from, to)` должен быть положительным, не более 366 дней; конец не позже текущего времени. `limit` — 1–1000, по умолчанию 500.

Ответ содержит список `data` в порядке времени. Пока `meta.next_cursor` не равен `null`, передавай его как `cursor`, сохраняя прежние `from`, `to`, `series` и `limit`. Для более длинного периода разбей его на непересекающиеся диапазоны; не пропускай и не дублируй границы.

## Успех и ошибки

Успех имеет оболочку `{ "data": ..., "meta": ... }`. `meta.warnings` объясняет ограничения данных; `meta.request_id` совпадает с заголовком `X-Request-ID`. Для `/price` различай дневную сводку по `data.kind: "daily_summary"`; одна цена имеет `kind: "telegram_snapshot"` или `"api_snapshot"`.

Ошибки приложения имеют Content-Type `application/problem+json` и поля `status`, `code`, `detail`, `request_id`, без оболочки `data/meta`.

| Ответ | Действие |
|---|---|
| `404 PRICE_NOT_FOUND` | Сообщи, что до указанного момента нет записи выбранной серии; проверь покрытие. |
| `404 DATA_GAP` | Сообщи о слишком старой записи. Не выдавай её за цену на запрошенный момент. |
| `404 SERIES_NOT_FOUND` | Исправь название серии. |
| `422 VALIDATION_ERROR` | Проверь формат даты, часовой пояс, диапазон и параметры пагинации. |
| `422 FUTURE_TIMESTAMP` | Объясни, что API не прогнозирует будущую цену. |
| `503 PRICE_STALE` | Текущая цена устарела; проверь `/coverage`. Не подставляй старую цену Telegram или прежнюю USDT-цену вместо текущей USD-цены Calcmula. |
| `503 DATABASE_UNAVAILABLE`, `500 INTERNAL_ERROR` | Сохрани `request_id`; допустима ограниченная повторная попытка, затем сообщи о недоступности. |

`/health/live` проверяет процесс, `/health/ready` — чтение базы. Они не подтверждают свежесть цены. Для свежести используй `/price/latest` или `data.collector.last_success_at` из `/coverage` (Unix seconds). `known_gap_count: null` означает неизвестное число пропусков, не ноль.

## Рабочие примеры

Дневная сводка за 5 февраля 2024 года по Москве:

```sh
curl --get 'https://gram.rin.ms/v1/ton/price' \
  --header 'Accept: application/json' \
  --user-agent 'GramPricesClient/1.0' \
  --data-urlencode 'at=2024-02-05' \
  --data-urlencode 'timezone=Europe/Moscow'
```

Одна цена на 12:00 МСК того же дня:

```sh
curl --get 'https://gram.rin.ms/v1/ton/price' \
  --header 'Accept: application/json' \
  --user-agent 'GramPricesClient/1.0' \
  --data-urlencode 'at=2024-02-05T12:00:00+03:00'
```

При ответе пользователю указывай валюту, дату/часовой пояс и источник. Для одной цены отличай запрошенное время от фактического времени записи; для сводки обозначай неполный день. Бери значения из полученного ответа API и сохраняй существенные предупреждения об источнике и пропусках.
